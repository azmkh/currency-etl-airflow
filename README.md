# Currency Exchange ETL Pipeline (Airflow + Astro CLI + MongoDB)

An **ETL pipeline** that runs every day and:

1. **E**xtracts the latest currency exchange rates from the free [Frankfurter API](https://frankfurter.dev/)
2. **T**ransforms them into a clean, consistent format
3. **L**oads them into **MongoDB**, where you can browse them with **Mongo Express**

```
 Frankfurter API ──► extract_rates ──► transform_rates ──► load_rates ──► MongoDB ◄── Mongo Express (web UI)
                         │    (XCom: raw_exchange_rates)    │  (XCom: transformed_exchange_rates)
                         └──────────────────────────────────┘
```

---

## 1. Key ideas for beginners

| Term | What it means here |
|---|---|
| **Apache Airflow** | A tool that runs your Python code on a schedule and shows each step's status in a web UI. |
| **DAG** | "Directed Acyclic Graph" – just Airflow's name for a *pipeline*: a set of tasks plus the order they run in. Ours is `currency_exchange_etl`. |
| **Task** | One step of the pipeline. We have 3: `extract_rates`, `transform_rates`, `load_rates`. |
| **XCom** | "Cross-communication" – Airflow's way to pass small pieces of data from one task to the next. |
| **Named XCom** | An XCom saved with a specific **key** (name), e.g. `xcom_push(key="raw_exchange_rates", ...)`, and read back with the same key. |
| **Astro CLI** | A command-line tool by Astronomer that creates and runs an Airflow project inside Docker with one command. |
| **Docker** | Runs each program (Airflow, MongoDB, Mongo Express) in its own isolated *container*. |
| **MongoDB** | A NoSQL database that stores JSON-like *documents*. |
| **Mongo Express** | A web page for viewing and editing MongoDB data. |

## 3. How each requirement is met

### 3.1 ETL pipeline with the Astro CLI
The project was created with `astro dev init` and is run with `astro dev start`.
It uses Astro Runtime 3.3 (Apache Airflow 3).

### 3.2 MongoDB and Mongo Express as Docker services
`docker-compose.override.yml` adds two services. The Astro CLI automatically merges this
file into its own Docker setup, so one `astro dev start` starts **everything**:

| Container | Purpose | Address |
|---|---|---|
| `api-server`, `scheduler`, `dag-processor`, `triggerer`, `postgres` | Airflow (created by Astro) | http://localhost:8080 |
| `mongodb` | The database (`mongo:7.0`) | `localhost:27017` |
| `mongo-express` | Web UI for MongoDB (`mongo-express:1.0.2`) | http://localhost:8081 |

### 3.3 Meta details on the Docker images
- **Airflow image** – `LABEL` instructions in the `Dockerfile` (maintainer, title, description,
  version, authors, vendor, licence…), using the standard `org.opencontainers.image.*` names.
- **MongoDB / Mongo Express** – the same kind of meta details under `labels:` in
  `docker-compose.override.yml`.

Check them:
```bash
docker inspect currency-etl_1344af-scheduler-1 --format "{{json .Config.Labels}}"
```
```bash
docker inspect currency-etl_1344af-mongodb-1 --format "{{json .Config.Labels}}"
```
*(The `1344af` part of the container name is generated by Astro; run `docker ps` to see yours.)*

### 3.4 Docker networking
A custom bridge network named **`currency_net`** is created. MongoDB, Mongo Express **and** the
Airflow containers are attached to it, so they can find each other by service name – that is why
the connection uses the host name `mongodb` instead of an IP address.

```bash
docker network inspect currency_net --format "{{range .Containers}}{{.Name}} {{end}}"
```

### 3.5 Persistent storage
Two **named volumes** keep MongoDB's data on disk outside the container:

| Volume | Mounted at | Stores |
|---|---|---|
| `currency_mongo_data` | `/data/db` | the database files |
| `currency_mongo_config` | `/data/configdb` | MongoDB config data |

So the data survives `astro dev stop` / `astro dev restart`. (Tested: 7 documents before and after a full restart.)

```bash
docker volume ls
```

### 3.6 The three tasks (`dags/currency_exchange_etl.py`)

| # | Task | What it does | XCom it **pushes** | XCom it **pulls** |
|---|---|---|---|---|
| 1 | `extract_rates` | Calls `https://api.frankfurter.dev/v2/rates?base=EUR&quotes=USD,GBP,JPY,CHF,CAD,AUD,CNY`, checks the response, records the time | `raw_exchange_rates` | – |
| 2 | `transform_rates` | Converts every API item into the required format | `transformed_exchange_rates` | `raw_exchange_rates` |
| 3 | `load_rates` | Saves the documents into MongoDB `currency_db.exchange_rates` | – | `transformed_exchange_rates` |

**Raw API item** (input of transform):
```json
{"date": "2026-11-08", "base": "EUR", "quote": "USD", "rate": 1.121}
```
**Transformed document** (exactly the required format):
```json
{
  "base_currency": "EUR",
  "target_currency": "USD",
  "exchange_rate": 1.121,
  "rate_date": "2026-11-08",
  "source": "Frankfurter API",
  "retrieved_at": "2026-11-08T12:36:53"
}
```
`retrieved_at` is the time (UTC) when the API was called.

**No duplicates:** the load step uses an *upsert* (update if it exists, otherwise insert) and a
unique index on `base_currency + target_currency + rate_date`. Running the DAG several times on
the same day updates the same 7 documents instead of adding copies.

### 3.7 Named XComs
The tasks do **not** use `return` values (which would create un-named `return_value` XComs).
Instead they push and pull with explicit keys:

```python
context["ti"].xcom_push(key="raw_exchange_rates", value=payload)                  # in extract
ti.xcom_pull(task_ids="extract_rates", key="raw_exchange_rates")                  # in transform
ti.xcom_push(key="transformed_exchange_rates", value=transformed)                 # in transform
context["ti"].xcom_pull(task_ids="transform_rates", key="transformed_exchange_rates")  # in load
```
You can see them in the Airflow UI: open a task in a DAG run → **XCom** tab.

## 4. How to run it (step by step)

### Prerequisites
- **Docker Desktop** installed and running
- **Astro CLI** – on Windows: `winget install -e --id Astronomer.Astro` (then open a new terminal)

### Steps
1. Open a terminal in this folder.
2. *(Only the first time on a new computer)* tell Astro to use Docker and create the `.env` file:
   ```bash
   astro config set -g container.binary docker
   ```
   ```bash
   cp .env.example .env
   ```
3. Start everything (first time takes a few minutes – it builds the image):
   ```bash
   astro dev start
   ```
4. Open the **Airflow UI**: http://localhost:8080 (local dev – no login needed).
5. Find the DAG **`currency_exchange_etl`**, switch it **on** (toggle), then click **▶ Trigger**.
6. Click the run → all three tasks should turn **green (success)**.
   Click a task → **Logs** to see its output, **XCom** to see the named XComs.
7. Open **Mongo Express**: http://localhost:8081 → login `admin` / `admin123`
   → database **`currency_db`** → collection **`exchange_rates`**.

### Useful commands
| Command | What it does |
|---|---|
| `astro dev start` | Start all containers |
| `astro dev stop` | Stop them (data is kept) |
| `astro dev restart` | Restart (needed after changing `Dockerfile`, `requirements.txt` or `.env`) |
| `astro dev pytest` | Run the tests in `tests/` |
| `astro dev logs -s` | Show the scheduler logs |
| `astro dev kill` | Stop **and delete** Airflow's containers/metadata (Mongo volumes are kept) |
| `docker ps` | List running containers |

Check the data from the command line:
```bash
docker exec -it currency-etl_1344af-mongodb-1 mongosh -u admin -p admin123 --authenticationDatabase admin currency_db --eval "db.exchange_rates.find({}, {_id:0}).toArray()"
```

### Troubleshooting
| Problem | Fix |
|---|---|
| `port is already allocated` | Another program uses that port. Postgres was already moved to **5435** in `.astro/config.yaml`; for others change the left number in `ports:` in `docker-compose.override.yml`. |
| Mongo Express shows *Unauthorized* | Log in with `admin` / `admin123`. |
| `load_rates` fails with an authentication error | Make sure `.env` exists and its password matches `docker-compose.override.yml`, then `astro dev restart`. |
| DAG is not visible | Wait ~30 s, or check `astro dev run dags list-import-errors`. |

> **Security note:** the usernames/passwords here are for local learning only. Never reuse them on a real server.
